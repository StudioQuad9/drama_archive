# 8. 既存8記事を下書きへ取り込む

## 今回作ったもの

`src/data/dramas.js` を読み、DBへの指示書を生成する。
本文・見出し・作品情報・引用・動画ID・画像パスを維持する。
原稿と表示の装飾は引き続き別々に管理する。

- `scripts/import-static-drafts.mjs`：変換と画像ファイルの存在確認。
- `supabase/imports/08-static-drafts.sql`：生成された取り込み用SQL。

これはDB構造の変更ではないので、migrationsには入れない。
GitHubへ送るだけでは実行されない。会社DBへの実行は下の手順で行う。
スクリプト自体はDBへ接続しない。

## Supabaseで行う操作

1. 会社の `commerce_engine` プロジェクトを開く。
2. SQL Editorで新しいクエリを作る。
3. `supabase/imports/08-static-drafts.sql` の全文を貼り付けてRunを押す。
4. 結果に8記事のslug・タイトル・revisionが出ることを確認する。
5. 管理画面で「一覧を更新」を押す。検索またはページ送りで8記事を確認する。

取り込み先はarticle_adminsに登録済みの管理者1人。
0人または複数人の場合は、所有者の取り違えを防ぐためエラーで停止する。
既存原稿は削除・更新しない。同じ所有者とslugの記事はスキップするので、
再実行しても重複せず、取り込み後に編集した内容も上書きしない。
そのため、既存の同slugの記事がある場合はそちらの内容を確認する。

## 公開と画像

取り込み先は非公開の下書き。公開中の記事や特集はこのSQLでは変えない。
管理画面で確認してから「公開する」を押す。
True Detectiveの特集指定も下書きに引き継ぐため、これを公開すると既存の
公開中の特集が切り替わる。他作品を特集にするなら公開前にチェックを調整する。

画像はまず `/pict/...` の既存ファイルを参照する。
これはStorageへのアップロードではない。サイト内の画像ファイルは残しておく。
必要に応じて管理画面のアップロード機能から画像を選び直し、保存・公開する。
追加画像には元データの段階で全作品にTrue Detectiveの画像が入っている。
元データをそのまま取り込むため、各作品を特集にする前に差し替えを確認する。

元の公開日時は `metadata.originalPublishedAt` に保存する。
公開サイトでの並び順に使う公開日時は、新しく「公開する」を押した時刻になる。

## SQLを作り直す場合

リポジトリで `node scripts/import-static-drafts.mjs` を実行する。
生成後はSQLの差分を確認する。元の記事ファイルや画像は削除しない。

## 検証

ローカルの検証用DBで、8件の取り込み・再実行時の重複防止・編集済み原稿の保護・
公開版が変わらないこと・管理者数が不適切な場合の停止を確認する。
会社DBでの取り込みは、上のSQL Editor操作後に確認する。
