# 5-3. 管理画面の改善と特集切り替えの確認記録

実装コミット：`ba66da9` 記事の公開操作・管理画面改善と特集の一件化を実装する
確認日：2026年11月12日

## この段階でできること

左側で過去の原稿を探し、右側で文章を書く構成に整理した。
画像は左側で扱い、YouTube動画IDは引用文・引用者より先に入力する。
引用の項目は特集画像に重ねるセリフと人物名のために残している。入力は任意。

検索は自分の保存済み原稿全体のタイトル・見出し・本文を対象にする。
一覧は更新日時の新しい順で1ページ10件。検索・ページ移動で編集中の原稿は消さない。
一覧に表示される記事と、右側で編集中の記事は必ずしも同じページに存在しない。
別の記事を選択したときだけ、右側の内容をその記事へ切り替える。

## 執筆から公開まで

1. 原稿を選ぶか、新しい下書きを開く。
2. 文章・作品情報・必要な画像を入力する。
3. 「記事をプレビュー」で、本番と共通のModal・DramaDetailを使って見た目を確認する。
4. 「下書き保存」で編集中の原稿をDBへ保存する。
5. 未公開なら「公開する」、公開済みなら「更新する」を押して読者向けの内容へ反映する。
6. 公開を取り下げたいときは「非公開にする」。下書きは残る。

公開状態の確認は自動で行う。執筆者に「再取得」を操作させるボタンは置かない。
通信エラー時は結果を確かめ、未反映なら内容の確認と再操作を案内する。
結果が分からない間は再送を止め、入力の保管と時間をおいた開き直しを案内する。

## 特集チェックの意味

「トップの特集にする」は、この記事をページ上部の特集へ割り当てる指定。
チェックして下書き保存した時点では、現在の特集は変更しない。
下書きでは複数の記事にチェックが付いていてもよい。

公開・更新を確定すると、以前の特集の公開版と下書きから特集指定を外し、
新しい記事を特集にする。以前の記事の本文や画像は保持し、通常記事として公開を続ける。
公開中の特集は同時に最大1件。特集を非公開にするなどして0件になる場合はある。

検証するときは、記事Aをチェックして保存・公開し、次に記事Bでも保存・公開する。
その後「一覧を更新」して記事Aを選び直すと、チェックが外れたことを確認できる。
下書き保存だけで確認すると両方にチェックが残るが、それは公開前の指定を保持する仕様。

## 実装の対応

- DraftWorkspace.jsx：検索、10件ずつの一覧、原稿選択、保存と各画面の連携。
- ArticleImages.jsx：左側の画像操作。
- DramaFields.jsx：作品情報・動画・引用の入力。
- FeaturedStatus.jsx：現在の特集名と切り替えの説明。
- PublicationControls.jsx：公開・更新・非公開と、結果の自動確認。
- DramaDetail/index.jsx と同じSCSS：本番とプレビューに共通の詳細表示。
- 20261112030000_single_featured.sql：以前の特集を外し、特集を最大1件に保つDB処理。

下書きはarticles、公開版はarticle_publicationsへ保存する。
公開版の複製により、下書き編集だけで読者向けの内容が変わらないようにしている。
特集切り替えはDB内でまとめて行い、失敗時は全体を取り消す。
古いタブからの上書きはrevision（原稿ごとの版番号）の照合で防ぐ。
