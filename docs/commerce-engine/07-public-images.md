# 7. アップロード画像の公開表示

## 何をするか

既存の画像ファイルを再アップロードせず、公開記事で使う画像だけを読者へ表示する。
記事カードはメイン画像、Featuredはメイン＋追加画像のスライダーに使う。
詳細モーダルは引き続きYouTubeと本文を表示する。

## 公開範囲

article-imagesバケットのPrivate設定は維持する。
Storageの閲覧ルールを追加し、article_publicationsのメイン画像または追加画像に
参照されているファイルだけを匿名でも読めるようにする。
下書きだけの画像は公開しない。同じ画像が別の公開記事で使われていれば読める。
アップロードの権限は管理者本人のフォルダのみのまま。PDF用の保存先には適用しない。

## 取得の流れ

DBのstorage://参照を /api/article-images/ユーザーID/ファイル名 へ変換する。
この小さなAPIは訪問者と同じ権限で60秒の閲覧URLを発行し、ブラウザを案内する。
ファイル本体はSupabase Storageから直接配信する。Vercelで画像本体を中継しない。
HTMLには固定の窓口URLを載せるので、ページを開いたままでも閲覧URLの古さに依存しない。
画像窓口はキャッシュせず、Next.jsの画像最適化キャッシュも通さない。
Secret keyや管理者権限を使わない。非公開にすれば新しい閲覧URLの発行は拒否される。
すでに発行したURLは最大60秒の有効期間があり、取得済みの画像やブラウザの
キャッシュを回収する仕組みではない。

## 反映するSQL

supabase/migrations/20261112040000_public_article_images.sql
をGitHub連携で適用する。コードを保存しただけでは会社DBの閲覧ルールは変わらない。
バケットをPublicへ手動変更したり、画像を再アップロードしたりする必要はない。

## ファイル

- src/lib/supabase/public-server.js：訪問者権限のサーバー接続を共通化。
- src/lib/articles/publications.js：共通接続を使用。
- src/lib/articles/publication-record.mjs：画像参照をサイトの取得先へ変換。
- src/app/api/article-images/[...path]/route.js：閲覧可能な画像URLへ案内する。
- DramaCard/index.jsx、ImageSlider/index.jsx：画像取得窓口を直接使う。
- 20261112040000_public_article_images.sql：公開記事が参照する画像だけ閲覧許可。

## 確認方法

1. SQL適用後、ログインしていない状態でトップページのカード・特集画像を確認。
2. Featuredのメイン＋追加画像が順番に出ることを確認。
3. 矢印・ページ送り・スワイプでは記事を開かず、画像クリックでは開くことを確認。
4. 未公開記事だけの画像は取得できないことを確認。
5. 非公開化後は、その記事だけで使っている画像の新しいURL発行が拒否されることを確認。
