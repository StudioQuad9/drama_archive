# 5. 公開・更新・非公開の操作

## 今回の範囲

ローカル管理画面から、すでにDBに用意したpublish_articleとunpublish_articleを呼ぶ。
新しいSQLやDB構造変更はない。コード追加だけでは記事を公開しない。
管理者が確認画面で操作を確定したとき、会社Supabaseの公開データが変わる。
トップページのDB接続は06で行う。公開画像の配信・Featuredの1件化は後の段階。
この段階でも公開版の文章・作品情報は匿名でDBのData APIから閲覧可能になる。

## ボタンの表示

- 未公開の記事：「公開する」。
- 公開中の記事：「更新する」。保存済み原稿と公開中の内容が同じなら押せない。
- 「非公開にする」：公開中の記事だけ操作できる。下書きは残す。
- 状態確認用のボタンは置かない。公開・更新・非公開の結果は自動で確認する。

公開・更新・非公開の操作後は、自動で状態を確認する。常設の再取得ボタンは置かない。

## 操作

1. 下書きを保存し、プレビューで内容を確認する。
2. 公開設定で「公開する」を押し、確認する。
3. article_publicationsへ保存済み原稿がコピーされ、「公開中」と表示される。
4. 原稿を変更して下書き保存しても、公開中の内容は変わらない。
5. 「更新する」で公開版を更新する。
6. 「非公開にする」で公開版を取り下げる。下書きは残る。

公開は保存済みのタイトルと本文が必須。未保存変更やアップロード中は公開不可。
版番号が一致しなければDB側でも公開を拒否する。
同じ版の更新を防ぎ、公開版と下書きの差分の有無を表示する。
初回公開日時は更新でも維持する。非公開後の新規公開では日時を付け直す。
非公開操作は現在の公開版を取り下げる。未保存の入力はそのまま残す。
公開操作中は保存・原稿の切替・ログアウトを止める。
通信失敗時も成功済みの可能性があるため、自動でDBを確認する。
確認が終わるまで公開・更新・非公開のボタンを押せないようにする。
操作した版が公開されていれば「公開しました」「更新しました」と表示する。
未反映なら入力を残し、内容を確認して公開・更新ボタンを押し直すよう案内する。
新しい版が別画面で保存されている場合などは、その原因に応じた案内を表示する。
確認自体が失敗した場合は成否を断定せず、入力を保管して時間をおいて原稿を
開き直すよう案内する。結果不明のまま再送を促さない。
非公開も同様に、公開版がなくなったことを確認して完了を案内する。

## 確認

テスト記事で公開→下書き変更→更新→非公開を行い、
article_publicationsの内容とsource_revision、管理画面の状態が一致することを確認する。
公開操作で原稿のrevisionは増えない。原稿保存時だけ増える。
実データの公開・非公開は利用者本人が確認して操作する。
